# 插件下载功能设计文档

> 版本：v1.0 ｜ 日期：2026-09-06 ｜ 状态：已实现

## 一、背景与目标

浏览器扩展（`extension/` 目录，Manifest V3）此前只能通过手工打包成压缩包（如仓库根目录的 `extension.rar`）分发给用户，流程繁琐且版本不透明。

**目标**：在 ERP 前端提供插件在线下载入口，用户点击即可获取最新版插件 zip 包，并获得安装引导，取代手工打包分发。

## 二、总体方案

```
┌─────────────┐  点击「插件下载」   ┌──────────────────────────┐
│  前端首页     │ ──────────────────▶ │  GET /api/extension/download │
│  快捷操作网格  │                    │  后端内存打包 extension/ → zip │
└──────┬──────┘                    └───────────┬──────────────┘
       │ 弹出安装引导弹窗                        │ Content-Disposition: attachment
       │ GET /api/extension/version            ▼
       └───────────────────────────▶ 浏览器下载 geekozon-extension-v{version}.zip
```

- **后端**：Flask 标准库 `zipfile` 内存打包，**每次请求实时生成**（插件源码仅几百 KB，无需缓存），不引入新依赖。
- **前端**：两个入口 —— 首页「快捷操作」网格 + 采集箱页头，共用同一下载函数。

## 三、接口设计

### 3.1 版本信息接口

| 项 | 说明 |
|----|------|
| 路径 | `GET /api/extension/version` |
| 鉴权 | 公开（与 `/extension/<path>` 一致） |
| 作用 | 读取 `extension/manifest.json`，供前端展示版本号 |

响应示例：

```json
{ "code": 200, "msg": "ok", "data": { "version": "3.0.2", "name": "GeekOzon ERP" } }
```

### 3.2 打包下载接口

| 项 | 说明 |
|----|------|
| 路径 | `GET /api/extension/download` |
| 鉴权 | 公开 |
| 作用 | 遍历 `extension/` 目录，`zipfile` + `io.BytesIO` 内存打包为 zip 返回 |

关键设计点：

1. **文件命名**：从 `manifest.json` 读取 `version`，命名为 `geekozon-extension-v{version}.zip`（如 `geekozon-extension-v3.0.2.zip`）；读取失败时回退 `geekozon-extension.zip`。
2. **zip 内部结构**：所有文件置于顶层目录 `geekozon-extension/` 下 —— 用户解压即得完整扩展文件夹，可直接在 Chrome「加载已解压的扩展程序」中选择，避免解压出散落文件。
3. **排除规则**：
   - 文件：`.DS_Store`、`Thumbs.db`、`desktop.ini`
   - 目录：`__pycache__`、`node_modules`、`.git`
4. **响应头**：`Content-Type: application/zip` + `Content-Disposition: attachment`（同源/跨域均会走浏览器下载，不受 CORS 限制）+ `Cache-Control: no-cache`（保证拿到最新版本）。
5. **安全**：接口无用户输入路径参数，仅读取固定 `EXTENSION_DIR`，无目录遍历风险。

实现位置：`backend/app.py` 的 `extension_download()` / `extension_version()`，与已有 `/extension/<path>` 静态路由相邻（复用同文件中定义的 `EXTENSION_DIR`）。

## 四、前端交互设计

### 4.1 入口

首页（工作台）右侧「快捷操作」网格第 5 个按钮：

- 图标：lucide `puzzle`，文案：**插件下载**
- 现有网格为 2 列布局，第 5 个按钮自动换行，无需改动样式

### 4.2 入口二：采集箱页头

「商品采集」页标题右侧按钮组（与「手动添加」并排）：

- 样式：`btn btn-ghost btn-sm`（次要按钮，不与主操作「手动添加」抢视觉），图标 lucide `puzzle`，文案：**下载插件**
- 直接复用首页定义的全局函数 `_downloadExtension()`（两页面脚本均在全局作用域加载），点击行为与安装引导完全一致

### 4.3 点击行为（`_downloadExtension()`）

1. **触发下载**：动态创建临时 `<a>` 标签指向 `${Api.BASE_URL}/api/extension/download` 并点击后移除。不用 `window.open`（避免个别浏览器弹窗拦截/残留空白标签页），不用 `fetch`（Api 模块是 JSON 封装，二进制流走原生链接最简单）。
2. **安装引导弹窗**：复用现有 `Modal` 组件，展示 4 步安装说明：
   - 解压下载的 zip 压缩包
   - 地址栏打开 `chrome://extensions`
   - 开启右上角「开发者模式」
   - 点击「加载已解压的扩展程序」，选择解压出的 `geekozon-extension` 文件夹
3. **版本回填**：弹窗打开后异步调用 `Api.getExtensionVersion()`，成功后在弹窗标题文案中回填「（v3.0.2）」；失败静默降级（不显示版本号）。

## 五、涉及文件清单

| 文件 | 改动 |
|------|------|
| `backend/app.py` | 新增 `GET /api/extension/version`、`GET /api/extension/download` 两个路由 |
| `frontend/js/api.js` | 新增并导出 `getExtensionVersion()` |
| `frontend/js/pages/home.js` | 快捷操作网格新增「插件下载」按钮；新增 `_downloadExtension()`（下载 + 安装引导弹窗 + 版本回填） |
| `frontend/js/pages/collect.js` | 采集箱页头按钮组新增「下载插件」入口，复用 `_downloadExtension()` |

**不引入新依赖**（zipfile/io 为 Python 标准库），**不改数据库、不改扩展本身**。

## 六、测试与验收

| 验证项 | 结果 |
|--------|------|
| `GET /api/extension/version` | ✅ 200，返回 `{version: '3.0.2', name: 'GeekOzon ERP'}` |
| `GET /api/extension/download` | ✅ 200 `application/zip`，`filename=geekozon-extension-v3.0.2.zip`，约 234KB / 47 个文件 |
| zip 结构 | ✅ 所有条目均在 `geekozon-extension/` 下，`manifest.json` 位于顶层目录内 |
| zip 完整性 | ✅ `testzip()` 无损坏 |
| 前端语法 | ✅ `node --check` 通过（home.js / api.js） |

**已知问题修复记录**：首版下载接口返回空文件 —— 打包后 `BytesIO` 读写指针停在末尾，`send_file` 读取时已到 EOF；在返回前补 `buf.seek(0)` 解决。

## 七、后续可选优化

- 删除根目录 `extension.rar`（本功能已取代手工打包分发）
- `docs/用户使用手册.md` 2.2 / 6.1 安装章节补充「可在 ERP 首页或采集箱页点击『插件下载』直接获取最新版插件包」
- 若插件体积显著增大（>10MB），可按 `extension/` 目录 mtime 缓存内存 zip，避免每次请求重复打包
